## 概述

Google DeepMind 这场访谈的价值，不是又一次解释“AI agents 会替你做事”，而是 Nenad Tomašev 把 agent 从产品 demo 拉回到系统工程与安全经济学。他的主线很清楚：当 agent 获得工具权限、能委托其他 agent、能在被投毒的 Web 环境中行动，并且数百万 agent 共享相似模型偏好时，风险就不再是“模型回答错了”，而是一个分布式行动系统会怎样失效。

他对 agent 的定义非常具体：

> **[1:44]** "an agent observes a state of the world and performs an action"

语言模型给出 prompt 的 continuation，agent 则观察世界状态并执行动作。中间的关键增量是 harness：

> **[2:16]** "there is a harness around it made to enact the changes once they have been proposed."

这意味着 agent 不是更聪明的 chatbot，而是被接入执行系统的语言模型。产品风险也因此从内容正确性升级为行动后果：邮件可能发错、钱可能花错、实验可能损坏硬件、委托链可能把任务拆坏。

## Agent 的核心增量是行动权，不是智力

Tomašev 一开始就拆掉一个常见误解：agent 与 LLM 的差别不是底层模型变成另一种智能，而是模型外面多了一层能把建议变成行动的执行壳。用户仍然用自然语言对话，但角色发生变化。

> **[3:25]** "you're more in the position of a decision maker to review and approve."

这句话对产品设计很关键。Agent 不是让用户“少看一点信息”，而是把用户从操作者变成审批者。审批者的任务不是每一步都亲自执行，而是判断哪些动作可以放行、哪些动作需要阻断、哪些动作需要人工复核。

因此 tool access 是 agent 产品的分水岭。Tomašev 用 Gmail 发邮件举例，agent 一旦能发出真实邮件，就从信息工具进入行动系统。

> **[4:16]** "there is a chance of it sending something wrong"

这也是为什么“人类在环”不能只是 UI 上放一个确认按钮。真正的问题是：系统如何知道哪些动作更敏感、更不可逆、更可能出错？如果无法给任务做风险分级，确认按钮会变成形式主义。

## 当前 agent 最可靠的 ROI 仍在可验证域

Tomašev 承认 coding agent 已经在加速软件开发：

> **[5:09]** "it's really accelerating the development of software"

原因不是代码天然神圣，而是软件任务容易闭环：写测试、跑测试、验证局部功能。可验证性让 agent 的错误可以被快速发现和修正。相反，越接近物理实验、医疗、采购、社交沟通和商业谈判，错误成本与验证难度就越高。

他对当前模型能力边界的判断很克制：

> **[11:43]** "a kind of a combinatorial closure of what you already know how to do."

> **[12:00]** "we have not yet seen these models be truly, deeply transformative."

这不是保守主义，而是对 agent 落地边界的校准。当前系统擅长把人类已有知识重组、补缝、组合和自动化；它们还没有稳定表现出“做出人类想不到的科学发现”的能力。对产品和组织决策来说，正确优先级应该是先把 agent 放在标准明确、反馈快、可回滚的任务上，再逐步进入开放式探索。

## 人类监督的敌人不是懒惰，而是 automation bias

Tomašev 对 human-in-the-loop 的提醒非常有用。他不是说“保留人工审核就安全”，而是说 agent 前几次做对后，人会自然降低警惕。

> **[6:30]** "automation bias"

> **[6:49]** "as soon as you switch off, you're rolling the dice."

这解释了为什么很多 agent 产品会在 demo 中显得安全，在长期使用中变危险。用户不是一开始就盲信，而是被系统的连续成功训练成盲信。真正的安全设计不能只依赖用户保持注意力，而要让系统主动暴露不确定性、记录决策依据、标记不可逆动作、对高风险操作强制减速。

他在科学自动化场景里也强调了同一件事：

> **[10:50]** "we need to have safeguards in place, and we need to have good, reliable protocols in place for these agents to close the loop."

在软件里 close the loop 靠测试；在材料、医疗、生物实验里 close the loop 要接触现实世界，反馈慢、成本高、后果不可逆。Agent 科学不是“让模型自己想一想”，而是要把实验调度、物理安全、协议约束和反馈分析接成一个可靠系统。

## 多 Agent 系统的瓶颈不是并行，而是委托

访谈中最有技术价值的部分，是 Tomašev 区分 parallelization 和 delegation。很多多 agent 系统只是把任务切块后并行执行，这能加速，但不等于智能委托。

> **[17:46]** "they act more as parallelization than delegation"

> **[18:20]** "this is not the intelligent delegation framework that we talk about."

他的婚礼例子看似轻松，实际指出了系统级语义断裂：

> **[18:23]** "one agent that is buying the wine and another one that is buying glasses"

如果两个 agent 都独立完成子任务，但没有共享“婚礼需要酒杯”这个上下文，结果仍然失败。多 agent 的核心不是多开几个 worker，而是要有任务分解、能力认证、上下文传递、异常处理和结果整合。

这也是为什么他强调 contract：

> **[19:33]** "you really want to emphasize verifiability and to be very formal about the contract"

未来 agent-to-agent 协议的关键不会只是消息格式，而是委托合同：任务边界是什么，成功标准是什么，失败如何回滚，哪些权限被授予，哪些结果必须被验证，哪些责任由 delegatee 承担。

## 任务可逆性应该成为 agent 产品的基础分类

Tomašev 给出了一个非常适合落地的风险分类：任务是否可逆。

> **[19:44]** "some are completely reversible."

> **[19:54]** "Some may have consequences in the real world"

这比泛泛地说“高风险任务需要人工确认”更可操作。可逆任务可以重跑、重委托、自动修复；不可逆任务涉及支付、发送、删除、提交、物理动作、外部承诺，必须提高验证强度。

他还提到一个常被忽略的反向委托：AI 向人类委托。在医疗影像里，窄 AI 系统可以在不确定时把判断交还给人类。

> **[22:35]** "it does make sense to delegate those decisions to humans at the very least"

这提示了 agent 产品的成熟形态：不是追求全自主，而是让 agent 学会何时放弃自主。最好的 agent 不是“不需要人”，而是能识别自己不该继续行动的边界。

## Agent trap 让开放 Web 变成不可信执行环境

安全部分是整场访谈的重心。Tomašev 的判断很硬：如果单次交互不能足够可靠，大规模系统会统计性失败。

> **[23:15]** "if there is not complete reliability of individual interactions, any system of scale that has many interactions is naturally going to statistically fail."

这不是安全洁癖，而是规模数学。一个 agent 一天交互几十次，错误率可以低；数百万 agent 互相交易、委托、访问网页，单点小概率错误会被规模放大。

Agent trap 的本质，是环境本身被投毒。网页里可以有不渲染给人类看的元素，非视觉 agent 读取 raw page 时会消费这些隐藏内容。

> **[24:54]** "hidden tokens that can make it do different things than what the intention was."

更进一步是 dynamic cloaking：

> **[25:03]** "dynamic cloaking"

恶意网站可以根据行为判断访问者是人还是 agent，然后只对 agent 展示被操纵的内容。Tomašev 还指出一个非常大的平台信号：

> **[26:22]** "the most of the web is currently being generated by agents and consumed by agents"

如果这成立，Web 正在从“人类阅读的网页”变成“agent 读写的执行环境”。传统广告、SEO、内容可信度、网页安全边界都会被重写。Agent 产品如果继续把开放 Web 当成可信工具源，规模化以后会被 prompt injection、dynamic cloaking 和环境级协调攻击系统性击穿。

## 分布式智能会把对齐问题从模型训练推向机制设计

访谈最后，Tomašev 给出最反直觉的 AGI 框架：我们可能不需要一个巨大的全能模型，而是一个专业化 agent 社会。

> **[38:31]** "humanity level intelligence"

> **[38:53]** "maybe we have instead a society of specialists"

他的理由很现实：专用棋类引擎比通用模型更快、更准、更便宜；很多任务也是如此。未来可能存在一个通用协调层，负责理解任务、调度资源、编排 specialist，而不是让一个 humongous model 做所有事。

这会直接改变 alignment 的对象。当前安全范式多数是在观察一个模型行为并对齐它：

> **[40:14]** "our alignment approaches as they exist at the moment have to do with taking one model"

但如果未来是 10,000 个 agent 动态交互、互相委托、咨询人类、调用工具，那么系统边界本身都不清楚：

> **[40:30]** "it's not super trivial to align that whole system suddenly or even to know what the system is"

Tomašev 给出的方向是借鉴人类社会：

> **[41:00]** "through economic incentives."

这意味着 agent safety 会从“训练一个好模型”扩展为“设计一套激励兼容的 agent 经济”。个体 agent 仍然要安全，但群体安全需要市场机制、认证、声誉、合约、权限、监管和惩罚结构共同作用。

## 关键判断

- Agent 的本质增量是行动权；harness 把语言模型的建议变成真实世界动作。
- Human-in-the-loop 的核心风险是 automation bias，用户会被连续成功训练成放松审核。
- 当前 agent 最可靠的场景仍是可验证域，尤其是软件；开放式科学发现和物理实验需要更强协议。
- 多 agent 系统现在多是并行化，不是真正委托；真正委托需要能力认证、正式合约和异常处理。
- 任务可逆性应该成为 agent 产品的基础风险分类，不可逆操作必须强制更高验证。
- 开放 Web 对 agent 来说是不可信执行环境，hidden tokens 和 dynamic cloaking 会让网页变成攻击面。
- 当 Web 由 agent 生成并由 agent 消费，广告、SEO、安全和内容可信度都会被重写。
- AGI 的实际形态可能是 society of specialists，而不是单一全能模型。
- 安全范式会从单模型 alignment 扩展到分布式 agentic economy 的机制设计。

## 深度关联
> 以下关联基于论点级分析：不是「都提到了X」，而是具体论点之间的逻辑关系

### Tomašev 把 Karpathy 的 agent 杠杆补上系统安全边界
**← [[Karpathy- Skill Issue — Code Agents, AutoResearch, and the Loopy Era]]**
- 本文件论点：Tomašev 认为 agent 的关键增量是执行动作，用户变成 review and approve 的 decision maker；但 automation bias 会让人类在连续成功后失去警惕 [1:44, 3:25, 6:49]。
- 对方论点：Karpathy 认为工程师要把自己从执行回路中移除，让 agent 以 macro action 的方式并行推进任务。
- 关联逻辑：Karpathy 描述“如何最大化 agent 杠杆”，Tomašev 描述“杠杆放大后如何失控”。两者放在一起说明，agentic engineering 不能只追求 token throughput，还必须设计风险分级、验证协议和人类注意力管理，否则移除瓶颈会同步移除最后的安全缓冲。

### Tomašev 为 Satya 的 harness 战略增加安全含义
**→ [[Satya Nadella- The Rise of the Full-Stack Builder]]**
- 本文件论点：Tomašev 认为 agent 是由 LLM 加 harness 构成，真正难点是 coordinating、orchestrating、managing，并防止委托链和环境投毒失效 [2:16, 13:51, 23:15]。
- 对方论点：Nadella 把 harness 定义为 models、data、tools 和 context layer 的循环，认为平台价值会转向开放 harness 和企业私有 eval。
- 关联逻辑：Satya 从企业平台价值说明为什么 harness 是新操作系统，Tomašev 从安全工程说明为什么 harness 也是新风险边界。两者共同指向一个判断：未来 AI 平台的核心能力不只是调用模型，而是治理模型、工具、数据、权限、委托和验证之间的闭环。

### Tomašev 与 Brown 共同否定单点能力叙事
**← [[Noam Brown- Test-Time Compute Changes Benchmarks, Safety and Research]]**
- 本文件论点：Tomašev 认为 future AGI 可能是 society of specialists，安全对象从单一模型变成动态 agent 网络 [38:53, 40:30]。
- 对方论点：Brown 认为模型能力不是静态属性，而是预算、test-time compute、scaffold 和任务类型共同决定的函数。
- 关联逻辑：Brown 从能力评估角度否定“一个模型一个分数”，Tomašev 从系统架构角度否定“一个模型一个智能体”。合起来看，AI 能力和 AI 风险都必须被建模为系统属性，而不是单个模型权重的属性。

### Tomašev 将 Dario 的多模型差异化推向分布式智能
**→ [[Dario Amodei- Why AI Won't Be a Monopoly]]**
- 本文件论点：Tomašev 认为专用系统会因为更快、更准、更便宜而形成 specialist society，通用层负责 orchestration [38:53, 39:13]。
- 对方论点：Dario 认为 AI 不会变成单一垄断，模型差异化比云服务更强，不同模型会在不同任务和风格上保留差异。
- 关联逻辑：Dario 解释为什么市场不会只有一个模型供应商，Tomašev 解释为什么系统架构也不应只有一个全能模型。二者共同支持“多模型、多专长、多调度层”的生态判断，但 Tomašev 进一步指出这种多元结构会把对齐问题推向机制设计。
