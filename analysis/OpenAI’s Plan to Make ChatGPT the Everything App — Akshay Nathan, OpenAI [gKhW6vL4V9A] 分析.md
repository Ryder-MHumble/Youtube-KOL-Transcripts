## 概要

Akshay 领导的团队叫 **productivity**（而非 enterprise 或 work），因为**个人生产力也算**（[00:09:04]）。本期围绕一个月前发布的 **ChatGPT Work** 展开：它把 Codex 的能力与 ChatGPT 的分发合并成所谓的"超级应用"，发布时同日上线新模型，已公布 **1000 万用户**（[00:42:26]、[00:43:26]）。

产品动因是一次内部观察：Codex 在 OpenAI 内部出现了**非开发者的采用拐点**——战略财务、市场等职能都在用，而且"**人们为自己在用 Codex 感到骄傲**，像是拥有了一种超能力"（[00:07:04]–[00:08:04]）。由此产生的产品问题是：ChatGPT 已有的巨大分发盘，怎么把这份 agent 能力交到他们手上。

## 核心观点

### harness 的合并：Codex 的壳吃掉了 ChatGPT 的壳

- **两个产品共用同一个 harness**。ChatGPT Work 与 Codex 底层能力一致，差别在 UX 取舍和沙箱默认值：Codex 模式会把 git 状态、diff 更前置；Work 模式则把这些细节抽象掉（[00:11:04]、[00:12:05]）。产品原则是"**不希望用户被困在某个 tab 或某种体验里而拿不到产品的全部能力**"（[00:10:04]）。
- swyx 想做一次"**harness 工程的口述史**"：ChatGPT 的 harness 从 o1 时代一路用到现在，如今实际上被 Codex 的 harness 取代了。Akshay 的回答是一个循环模型——"**发散、收敛、发散、收敛**"（[00:16:10]）：
  - **chat 侧**长期优化的是**延迟与人格**（搜索、学习、写给亲友的消息这类用例）；
  - **Codex 侧**学到的是"**给 agent 一个无限灵活的环境——一台计算机——它能做到非常强大的事**"。
  - 面向知识工作时，"**把它带到这个计算机环境里更自然**"，再把计算机的细节对不习惯的用户抽象掉。
- ⚠️ 但他明确**不认为这是终局**："我们希望能力在所有地方都在……以后肯定还有工作要让各场景能力等同。"（[00:17:11]）
- 经典 ChatGPT harness **仍然存在**：开新对话不进 Work 就是它（[00:15:09]）。**由模型来做路由决策**——比如要建电子表格时会推你去 Work 模式（[00:15:09]）。

### 为什么要合并而不是分开：职能边界正在模糊

这是本期最完整的一条产品论证（[00:13:07]–[00:14:07]）：

> "我们所有人的工作都在因为 AI 剧烈变化，**几乎每几个月一变**。我感觉一觉醒来就在做和几个月前完全不同的事。"

因此按"**你是谁**"划硬边界会很难——只写代码的人、写战略文档的人、做市场的人、办活动的人之间的界线会被模糊掉。产品结论：**让用户自己选，但不要把用户框死**。落到工程上就是保持原语统一（比如 **plugins 在 ChatGPT、Work 和云端是统一的**）。

**Codex 作为品牌会继续存在**，而且他把话说得更强：不只是保留，"**开发者一直是我们的核心市场，我们会继续把 Codex 做得对软件开发特别好**"；合并**反而**提升 Codex 的效用，因为你可以在写 diff、生成 artifact、搜索代码之间无缝移动（[00:44:27]–[00:45:28]）。

### 模型选择：默认应该就是最好的

- "我们希望**对默认值有主见**……为绝大多数用例，默认就该是最好的。"高级用户有旋钮（推理档位、模型档次），"**可以说现在旋钮可能太多了，我们正在简化**"（[00:18:11]–[00:19:11]）。
- 给出的多智能体/高档位使用准则（[00:20:11]）：
  - **ultra / 多 agent 设置**适合**极复杂的开放式探索**或**高度可并行**的任务；
  - **goal 模式**适合"**能随时间取得可验证的一致进展**"的任务；
  - **但大多数任务两类都不属于**，尤其在刚开始的时候——所以先用默认配置，再看要往哪调。
- 一个产品化细节：模型选择被**投影到一维滑块**上（一端速度与效率、另一端质量与彻底性），"即使背后是多维的"（[00:21:12]）。
- ⚠️ **Ultra 发布后被回退了默认值**：发布时"**我们对 Ultra 是给谁用的没有足够主见**"，之后改成**需要手动开启、藏进高级设置**——因为它面向理解后果的高级用户，且会更快耗掉额度（[00:55:32]）。这是本期唯一一处明确承认的产品回退。

### Artifacts 与 Sites：新的知识工作载体

- **artifacts 是本次发布的重点投入**，模型侧和产品侧同时推进；他强调与前两代模型相比 **artifact 质量有相当显著的提升**（[00:22:12]–[00:23:12]）。
- swyx 演示了 agentic 编辑 Excel 文件（"你从没买过 Excel 授权"）。Akshay 的框定值得记：**这不是"你不再需要 Excel 授权"，而是"这是第一阶段"**——重点是你要**迭代**，而**高保真地呈现同事将看到的样子**才让人敢信任这个迭代过程（[00:23:12]）。
- ⚠️ **Sites 是他认为被低估的那一个**（[00:26:12]–[00:27:12]）：外界主要把它当原型工具（模型滑块本身就是在 site 里由设计、工程、产品共同打磨出来的），但另一面是 **site 作为知识工作的 artifact**——公司财务团队的月度报告**从幻灯片和电子表格搬到了 site 上**，因为 site 带宽更高：PowerPoint 和 Excel 无限灵活，但总会撞到"人不会用某个功能"或"产品不支持"的边界，而 **site 里你想要什么就能要到什么**。
- 一条正在成形的方向：**多人协作的 artifact**。他讲的内部场景是"有人问我事，我去问 ChatGPT Work，再把答案转发回去"——"**我是不是根本不需要在这个回路里**"（[00:24:12]）。swyx 立刻指出这里有**权限层问题**：你实际上充当了权限层，"我能查的东西你未必该看到"（[00:25:12]）；Akshay 承认"agent 能访问的上下文是**极其个人的**，这必须被保护住，肯定是个挑战"。
- 术语现实：**artifacts 是内部叫法，外部没人这么说**——"如果 ChatGPT Work 擅长做幻灯片，他们就说它擅长做幻灯片，**而这正是我们想要的**"（[00:45:28]）。

### 与 OpenClaw 的关系

- swyx 点名 2026 年 7 月的 **OpenClaw** 现象："很多人第一次真正把 agent 用到个人事务上"。Akshay **说了自己的 OpenClaw 时刻**：他和配偶用它管家里的事、接上日历自动建事件，"**确实挺有用**"，后来跑它的笔记本坏了就没再捡起来（[00:46:28]）。
- 他承认**灵感来源**：ChatGPT Work 在 web 和 mobile 上给你一个**持久的计算机环境**，文件跨会话保留；"**我们团队有成员已经把过去用 OpenClaw 做的事完全转到 ChatGPT Work 上了**"（健身计划、饮食记录）——因为**原语是一样的**：定时任务、文件系统、跨时间引用（[00:46:28]–[00:47:28]）。
- ⚠️ **他明确不认为 ChatGPT Work 会取代 OpenClaw**："**我不这么认为**……那个团队做出来的这种了不起的开源技术永远有其需求；我们能做的是从中汲取灵感，把这份魔力带给听说过、用过 ChatGPT 的那多得多的人。"（[00:47:28]）
- 但产品目标本身是"万物应用"式的：**你来到这个产品、开一个会话，就能做任何事，不用点按钮跳去别处**；靠**可扩展的 plugin 系统**接上你需要的工具（[00:47:28]–[00:48:28]）。他自己试过用 finances plugin 做退休规划与预算，"**至少对我那部分已经被替代了**"，但补了一句限制——**ChatGPT 还不为你托管现金和资产**（[00:48:28]–[00:49:29]）。

### ⚠️ 关于"即时拉取够不够"的一次未正面回答

swyx 从数据工程角度追问：只靠 MCP / CLI / API **即时拉数据**是不够的，你还是想要数据仓库、缓存或语义层（[00:50:29]）。Akshay 的回答留了余地：**取决于访问模式**——要立刻回答确实很难；但 ChatGPT Work 想支撑的很多用例**本来就不需要立即返回**，而是交给 agent 去跑一段时间的任务，且有**程序化工具调用和子 agent**可并行化；他的结论是"**MCP 与调用第三方服务的能力上限已被大幅抬高**"（[00:50:29]–[00:51:29]）。**他没有确认也没有否认内部是否存在缓存/语义层**——本页据此不做推断。

### 记忆

- 他把记忆放在**用户之爱的第一位**："和朋友、家人聊他们喜欢 ChatGPT 什么，**'它了解我'、'我的 ChatGPT 是我的'** 大概排第一。"（[00:56:33]）
- 机制：**ChatGPT Work 与云端默认继承 ChatGPT 的记忆**，并可写回；属于同一套 **memory V3 系统**（[00:56:33]）。
- 他不做记忆本身，因此对"召回的假阳性多还是假阴性多"不给结论，但给了框架：一是**要知道关于你的事**，二是要有**EQ 在恰当时机主动提起**、且是正向惊喜而非负面（[00:57:33]）。
- 对"work 场景的记忆是不是和 chat 根本不同"这一前提，他**直接反驳**：chat 里大量一次性对话"**长期累积起来相当耐久，是对我这个人相当好的表征**"，所以把它带进 work 产品才有价值（[00:58:35]）。
- **Chronicle**（从你如何使用计算机中学习的记忆输入源）目前是**实验性、默认关闭**，他建议试试（[00:59:36]–[01:00:37]）。他给的价值定位很克制：它未必能捕捉你的全部意图，"**但它多半会发现一些你自己都不知道的东西**"，在你做任务时主动浮出来就有用。

### AI 时代的组织与生产力度量（本期最有转述价值的一段）

- **岗位边界模糊**：EM / PM / 工程师 / 设计师之间的界线在模糊（[01:02:38]）。他的模型是 **T 型**——"**AI 会让每个人都成为通才**"（他举例自己以前做不出设计，现在能在 AI 帮助下迭代，尽管仍缺视觉品味），同时保留一条向下深挖的专长竖线（[01:03:39]）。
- **瓶颈变成了什么**："**瓶颈变成了想法和品味**……因为现在人人都能造，这真的是自下而上的野心的时代；因为要造的东西太多，**你永远会被你在任一时刻拥有的想法数量卡住**。"（[01:04:39]）
- ⚠️ 但他**不认为想法能被模型自动化**——swyx 说"我最想要但一直不work 的自动化是'给我带来新想法'，LLM 就是不行"（[01:04:39]）。Akshay 的回应是**想法不在真空里产生**：它们来自和用户对话、来自你看到的摩擦和反馈、来自已有的基础，"**所以那种能闭环、能把想法扎根在反馈里的通才，永远有价值**"（[01:05:39]）。
- **团队会变小吗？** 他的答案是**不会**："**个人或小团队能完成过去需要更多人的事，但同时要做的事也更多了，所以团队变得更有野心。**"（[01:02:38]）
- **生产力怎么度量——他明说没解决**（[01:06:39]–[01:07:40]）：
  - "**我们还没想明白。**"原因是目标极其多样，真正的度量是"用户达成其目标的能力"，而在不知道目标是什么、又要为每个人定制的前提下极难。
  - **点赞点踩没用**："你不知道他踩的是答案内容、是语气、还是有没有帮他达成目标。"
  - **旧代理指标正在失效**：过去用代码提交数、代码行数、story point 之类的**代理指标**，"**现在 token 用量、PR 数量已经不再那么强相关于团队能否达成目标**"，需要新的度量，"**而且整个行业都得想明白这件事**"。
- **他给管理者的具体建议**：看 **at-bats（上场次数）**——不只是数量还要质量：能不能高效走完"产生想法 → 造出来 → 拿到反馈 → 对反馈作出反应 → 证实或证伪假设 → 进入下一个想法"的整环；同时也包含团队文化——**有没有谦逊、能不能反复走这个过程还保持动力**（[01:08:41]）。
- **最锋利的一句**（[01:09:42]）：
  > "陷阱大概是**混淆 motion 与 progress**。因为有了这些工具，**motion 比以往任何时候都容易**；但 progress 要求你对自己到底想达成什么非常明确、非常刻意。"

### 企业落地：没有万能解

- 早期 ChatGPT Enterprise 的教训："企业里**没有一刀切的方案**。"当年大家都很兴奋、成立 AI 部署团队、预算巨大，但你问"具体想解决哪个用例"，答案的**方差爆炸式扩大**（[00:04:02]）。
- 他对这个box 的诊断很准："**你有一个盒子，可以对它说任何话，这是魔力；但反过来也意味着你不知道该拿它做什么。**"（[00:05:02]）
- 当前状态：采用在快速增长，早期采用者"**真的懂**"（保证上下文对、接对工具、做好监督，则一切皆有可能），**但还有大 10 倍到 100 倍的市场尚未理解这件事**——那才是 ChatGPT Work 想打的地方（[00:06:02]）。
- 产品方法论上他反复回到 **show, don't tell**："我们还没完全破解**如何展示而不是教**给用户能做什么。"（[00:34:20]）落到 UI 上是那对张力：**既要给足表达面（能说清需求、能验证用了对的工具和来源），又要让 UI 退到一边**（[00:31:18]–[00:32:19]）。
- 他自己给的**高级用户建议**（[00:37:23]–[00:39:23]）：
  1. **不断拓宽对"可能性"的想象**——他举绩效评估周期为例：半年前试过完全没用，这次"**模型做得比我好得多**"，因为它能拉到代码、评审、Slack 里的全部上下文，指出连他都没看到的成果；
  2. **喂得越多，回报越大**——artifact 存进 library、跨时间可引用，模型会以你想不到的方式主动调用；
  3. ⚠️ **但他明确划线**："我**绝不会**只用 AI 写出一份东西然后当作对某人的评估交上去。我说的是**收集上下文**。"swyx 归纳为"**agentic search**"，他接受这个说法（[00:40:24]）。
- 采用序列他说得很清楚（[00:35:22]–[00:37:23]）：**开发者 → 通用知识工作 → 所有人**。开发者是历史上的早期采用者、愿意忍受摩擦；往知识工作走需要新能力（artifacts、computer use）和"show not tell"；再往所有人走是同样的学习迁移。

## 与本库其它观点的关系

- **与 [swyx 自己反对模型路由的立场](20260710-latent-space-swyx-agent-labs.md) 的对照**：swyx 主张"以路由为傲就永远吃不满任何一个模型的完整能力"；本期 OpenAI 的做法是**由模型自己做路由**（chat ↔ work 模式切换）并**对默认值有主见**。这不是同一层的路由（一个是跨厂商，一个是同厂商内的模式选择），但把"谁来决定用哪个能力"这件事推给了模型——与 swyx 那句"人们不想选用哪版 AGI，他们只想让 AGI 替他们决定"是一致的（[00:10:04]）。
- **[LLM OS 与新计算范式](https://github.com/nolimitkun/ai-kol-wiki/blob/main/topics/llm-os.md) 的一次产品化实证**：持久计算机环境 + 文件系统 + 定时任务 + plugin，这几乎就是 Karpathy 的 LLM OS 清单被逐项落成产品。而 Akshay 自己把参照系指向 **OpenClaw** 而非操作系统——见 [Peter Steinberger](https://github.com/nolimitkun/ai-kol-wiki/blob/main/people/peter-steinberger.md) 与 [Gavriel Cohen（NanoClaw）](https://github.com/nolimitkun/ai-kol-wiki/blob/main/people/gavriel-cohen.md)。**⚠️ 值得注意的是他不认为会取代 OpenClaw**，而 swyx 在本期直接说出了"个人 OS"这个词。
- **"瓶颈是想法和品味"顶到 [AI 与就业](https://github.com/nolimitkun/ai-kol-wiki/blob/main/topics/ai-and-jobs.md)**：这与本库已有的 T 型/通才叙事同族，但他补的限定很重要——**想法不在真空里产生**，因此"能闭环、把想法扎根在用户反馈里的通才"才是稀缺项，而不是纯粹的创意。这对"AI 让人人成为创意工作者"的乐观版本是一条约束。
- **"混淆 motion 与 progress"是本库对 [AI 商业化与价值捕获](https://github.com/nolimitkun/ai-kol-wiki/blob/main/topics/ai-business-and-value-capture.md) 里"企业买了 AI 却没变化"现象的最简洁诊断**，与 [Steven Sinofsky 的"企业里所有有趣的事都是例外处理"](https://github.com/nolimitkun/ai-kol-wiki/blob/main/people/a16z.md)、[Mark Cuban 谈企业落地难](20260721-all-in-mark-cuban-ai-bubble.md) 属同一族问题的不同切面。
- **"旧代理指标正在失效"给 [评估与 Benchmark](https://github.com/nolimitkun/ai-kol-wiki/blob/main/topics/evaluation-and-benchmarks.md) 补了一条组织侧的观察**：本库此前讨论的是模型评测，这里是**用模型的人怎么被评测**——代码行数、PR 数、token 用量都不再与目标达成强相关，而**新的度量还不存在**。这是一条罕见的、来自前沿实验室内部的"我们不知道"。
- **记忆条线**：与 [Dan Biderman 谈"为什么长上下文还不够"](20260713-latent-space-dan-biderman.md) 直接对读——Biderman 讲机制，本期讲产品侧的两难（知道你的事 vs. 有 EQ 在对的时机提起），以及 Chronicle 这种"从你用电脑的方式里学"的新输入源。
- **权限层问题**是本库 [LLM 安全](https://github.com/nolimitkun/ai-kol-wiki/blob/main/topics/llm-security.md) 里一个新角度：多人共享 artifact 时，**人本身充当了权限层**，一旦被 agent 取代，"我不该看到的东西"就没有天然屏障——且**当事人无从知道自己不知道什么**（[00:25:12]）。
